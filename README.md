# PUFService

Windows-программа для осциллографа FNIRSI 2C53T с доработанной прошивкой RU_USB4 (USB CDC).
Бэкенд на Go (без cgo, без сторонних модулей), интерфейс — встроенная HTML/JS-страница,
которая открывается в окне Edge/Chrome в режиме приложения (`--app`).

## Структура

| Файл / папка | Назначение |
|---|---|
| `main.go` | HTTP-сервер на 127.0.0.1:53153, приём кадров с COM-порта, разбор `FS53`/`MR53`, SSE-поток в интерфейс, API (`/api/*`), записи с диска прибора, настройки, сохранение файлов, запуск окна и автозавершение |
| `update.go` | Самообновление: проверка `dist/version.json` через GitHub API, скачивание `dist/PUFService.exe`, сверка SHA-256, замена exe и перезапуск |
| `build_release.sh` | Сборка exe в `dist/` и запись `dist/version.json` для самообновления |
| `sys_windows.go` | Всё, что специфично для Windows: COM-порт через kernel32 (`CreateFile`, `SetCommState`…), поиск порта прибора в реестре (VID 2E3C / PID 5740), список дисков, папки, запуск Edge/Chrome, `MessageBox` |
| `sys_other.go` | Заглушки для Linux/macOS (только для разработки с имитатором) |
| `sim.go` | Имитатор прибора: `--sim` генерирует кадры, отвечает на команды кнопок, периода кадров и чтения памяти; `PUF_SIM_SCENARIO=sync` — 40-секундный цикл «CH2 нет → появляется на 45 Гц → подгоняется к сети» для проверки регистратора |
| `web/` | Интерфейс (встраивается в exe через `go:embed`) |
| `web/app.js` | Вся логика: график, стабилизация, лента, полная запись, спектр, пульт, диагностика, записи, датчики, синхроскоп, мощность, пуск, ШИМ, обороты |
| `web/core.js` | Чтение файлов прибора (.bin + .bmp, распознавание шкал со снимка) и измерения |
| `web/tape.js` | Накопление «ленты» (сшивка кадров в режиме самописца) |
| `res/` | Иконка и ресурс версии для exe (`app.rc`, `app.ico`) |
| `rsrc_windows_amd64.syso` | Скомпилированный ресурс (иконка + версия), Go подхватывает его автоматически |

## Сборка

Нужен Go 1.22+ (проверено на 1.24). Сторонних зависимостей нет.

```bash
# Windows exe (из Linux, macOS или Windows)
GOOS=windows GOARCH=amd64 go build -ldflags "-H windowsgui -s -w" -o PUFService.exe .
```

В Windows (PowerShell):

```powershell
$env:GOOS="windows"; $env:GOARCH="amd64"
go build -ldflags "-H windowsgui -s -w" -o PUFService.exe .
```

`-H windowsgui` убирает консольное окно. Без него удобно отлаживать: в консоль пишутся ошибки.

## Запуск для разработки (без прибора)

```bash
go build -o puf_dev .
./puf_dev --sim --nowindow        # имитатор прибора, сервер без окна
# открыть http://127.0.0.1:53153/ в браузере
```

`STUDIO_ROOTS=/путь/к/папке` (вне Windows) — где искать папки `Screenshot file` / `Screenshot simple file`.

## Иконка и версия exe

При смене версии поправьте `AppVersion` в `main.go`, `v1.x.x` в `web/index.html` и `res/app.rc`, затем пересоберите ресурс:

```bash
cd res
llvm-rc -no-preprocess -fo app.res app.rc
llvm-cvtres /machine:x64 /out:../rsrc_windows_amd64.syso app.res
```

(в Windows можно `windres app.rc -O coff -o ../rsrc_windows_amd64.syso` из MinGW или утилиту `rsrc`/`go-winres`).

## Протокол прибора (прошивка RU_USB4)

USB CDC-ACM, VID `0x2E3C`, PID `0x5740`, скорость порта не важна (виртуальный COM).

**Кадр экрана**, ~30 раз в секунду, всё little-endian:

```
"FS53" | ver(1) | seq(1) | len(u16) | G[0..127] | trace[602] | sys[16] | keyLatch(u16) | keyPhys(u16) | scanCnt(u8) | queue(u8) | injKey(u8) | 0 | sum16(u16)
```

- `G` — первые 128 байт структуры настроек (адрес 0x200000F8): `G[0x2D]` развёртка (индекс 0…28, 10 нс…20 с/дел), В/дел CH1 = `G[6]*3+G[2]`, CH2 = `G[7]*3+G[3]` (индекс 0…12, 10 мВ…100 В), `G[0x14]` маска каналов, `G[4]`/`G[5]` смещение нуля каналов (int8, точки), `G[0x1A..0x1B]` позиция триггера (int16).
- `trace` — 301 точка CH1 + 301 точка CH2 (экранные значения, 128 = центр, 25 точек на деление).
- `sys` — `G[0xF60..0xF6F]` (язык, страница, курсор меню).
- `sum16` — сумма всех предыдущих байтов кадра.

**Ответ на чтение памяти:**

```
"MR53" | 1 | seq | len(u16) | addr(u32) | data[n] | sum16
```

**Команды в прибор** (байты в COM-порт):

| Команда | Байты | Действие |
|---|---|---|
| Нажать кнопку | `A5 'K' idx hold` | кнопка 0…14 удерживается `hold` опросов (короткое ≈6, длинное ≈90) |
| Отмена | `A5 'X' 0 0` | очистить очередь нажатий |
| Период кадров | `A5 'P' ms 0` | период отправки кадров, мс (≥10) |
| Чтение памяти | `A5 'M' addr(u32) len(u16)` | ОЗУ 0x20000000…0x20038000 или флеш 0x08000000…0x08100000, до 2048 байт |

Полная запись захвата: буфер А (CH1) `0x200006A8`, буфер Б (CH2) `0x20000AA8`, по 1024 байта.
Шаг точек относительно экрана программа определяет сама, сопоставляя кадр экрана с буфером (`deepMatch` в `app.js`).

## Локальный API

Сервер слушает только `127.0.0.1`. Чтобы другие страницы, открытые в браузере, не могли управлять прибором
(порт фиксированный — 53153), все `/api/*`, кроме `/api/ping` и `/api/events`, требуют заголовок `X-PUF: 1`;
запросы с чужим `Host` (DNS rebinding) или чужим `Origin` отклоняются (403). Интерфейс добавляет заголовок сам (`api()` в `app.js`).

## Особенности FNIRSI 2C53T, которые учитывает программа

- Минусы CH1 и CH2 соединены между собой и, при подключённом USB, с землёй ПК — на страницах «Синхроскоп», «Мощность»
  и «Датчики» есть предупреждение; к сети — только через изолирующие датчики.
- Полоса 50 МГц (собственный фронт ≈ 7 нс) и 250 МВыб/с (4 нс на точку; на быстрых развёртках точки экрана интерполированы):
  страница «ШИМ» помечает фронт как «≤», если он упирается в эти пределы.
- Прошивка держит одно чтение памяти за раз: чтения с «Диагностики» и чтение полной записи стоят в одной очереди.

## Самообновление

Кнопка «Проверить обновления» / «Обновить» — на странице «О программе»; при запуске программа тихо проверяет сама,
и значок версии в шапке становится оранжевым, если есть новая.

- Источник — репозиторий `pufuna/oscil`, ветка по умолчанию, файлы `dist/version.json` и `dist/PUFService.exe`
  (через GitHub API). Для публичного репозитория ничего настраивать не нужно; для приватного — ключ доступа
  (fine-grained token, «Contents: Read-only» только для этого репозитория) в «О программе» → «Ключ доступа GitHub».
  Ключ хранится в `%APPDATA%\PUFService\update.json` и в интерфейс не возвращается.
- Скачанный файл сверяется с SHA-256 из `version.json`; при несовпадении обновление отменяется.
- Запущенный exe переименовывается в `PUFService.exe.old`, на его место встаёт новый, программа перезапускается
  с `--updated` и тем же адресом; открытое окно само перезагружается, `.old` удаляется новой версией.

Выпуск новой версии: поднять `AppVersion` (main.go), `v…` в `web/index.html` и `res/app.rc` (+ пересобрать `.syso`),
затем `./build_release.sh "что нового"` и закоммитить `dist/` в ветку по умолчанию.

Проверка без GitHub: `PUF_UPDATE_API=http://127.0.0.1:8899` — адрес, где лежит `repos/pufuna/oscil/contents/dist/…`.

## Изменения

**1.6.1**
- «Несущая ШИМ, Гц» на странице «Синхроскоп»: фильтр основной гармоники берётся ровно в один период несущей и полностью
  гасит её и её гармоники. При несущей 800 Гц ошибка угла по полной записи — типично 0,1° (95 % ≤ 3°) вместо 3° (до 9°)
  со старым фильтром 0,8 мс. Действует на синхроскоп, мощность, анализатор, регистратор, тренд пуска и измерения частоты.

**1.6.0**
- Просмотр записей (многокадровых CSV и событий регистратора) как в плеере вместо ползунка:
  ▶/⏸ с реальным темпом записи и скоростью ×0,25…×4, шаг по кадрам, в начало/конец; клавиши ←/→ (Shift — по 10), Пробел, Home/End.
- Обзорная лента всей записи под графиком: огибающая каждого кадра по обоим каналам, текущий кадр, момент срабатывания;
  щелчок/протягивание — переход, колесо — по кадрам.
- Режимы: «Кадр»; «Лента кадров» — все кадры подряд, как плёнка (колесо — масштаб, перетаскивание — прокрутка,
  щелчок — выбрать кадр, при отдалении — огибающая); «Наложение» — все кадры полупрозрачно друг на друге.
- Один масштаб на всю запись (по В/дел прибора из файла или общему автомасштабу) — при перелистывании шкала не скачет.
- «Запись» на осциллографе пишет время каждого кадра («от начала, с»).
- Регистратор: «▶ Смотреть» открывает событие в плеере без сохранения файла; щелчок по тренду выбирает кадр.
- Длинные графики: шкала времени и сетка подстраиваются под масштаб (раньше подписи слипались).

**1.5.3**
- Интерфейс не «прыгает» при нестабильном сигнале: постоянный набор ячеек измерений (недоступные — «—»),
  плашки над графиком не переносятся на вторую строку, фиксированная высота текстов стабилизации, статуса
  синхроскопа и примечаний, плитки фиксированной высоты (длинные подписи — с многоточием и подсказкой),
  плитки синхроскопа при кратком отсутствии расчёта остаются (бледнее), а не пропадают.

**1.5.2**
- «Управление прибором» перенесено наверх правой колонки страницы «Осциллограф» — видно вместе с сигналом без прокрутки.

**1.5.1**
- Окно программы больше не «засыпает» в фоне: Edge/Chrome запускается без замедления таймеров для свёрнутых и перекрытых окон
  (тренд «Пуска», чтение полной записи, завершение событий регистратора шли в фоне раз в секунду и реже).
- Тренд «Пуска» считается по приходу кадров (каждый новый снимок), а не по таймеру.

**1.5.0**
- Анализатор качества (новая страница): гармоники до 25/40/50-й (по полной записи прибора, окно — целые периоды),
  КНИ (THD), чётные/нечётные, отклонение частоты и напряжения, постоянная составляющая, коэффициенты амплитуды и формы,
  K-фактор и TDD для тока, максимум КНИ, усреднение 3/10 с. Для напряжения — нормы ГОСТ 32144-2013 по каждой гармонике
  и КНИ (классы сети 0,38 / 6–25 / 35 / 110–220 кВ). Если CH1 — В, а CH2 — А: активная мощность каждой гармоники и её
  направление (сеть → нагрузка / нагрузка → сеть). CSV и PNG.
- Самообновление из GitHub (см. выше).
- Имитатор: в CH1 типичные гармоники сети (3-я 1,5 %, 5-я 4 %, 7-я 3 %).


**1.4.0**
- Регистратор событий (новая страница): запись кадров с предысторией по триггерам — начало синхронизации (|Δf| < порога),
  синхронизм достигнут, угол Δφ в окне, подача напряжения, провал/пропадание, бросок, уход частоты, а также «Записать сейчас».
  Триггеры с гистерезисом и паузой 2 с между повторами; повторное срабатывание продлевает запись; автосохранение и «снова ждать».
  Пишется последовательность кадров прибора (CSV открывается в «Записях» с ползунком кадров) и тренд СКЗ / f / Δf / Δφ по каждому кадру.
- Шкала по Y на графиках: значения делений CH1 слева, CH2 справа, с учётом В/дел, нуля и коэффициента датчика (переключатель «Шкала по Y»).
- Полная запись: PNG и CSV сохраняют именно её (раньше — скрытый экранный график / 301 точку); «Пауза» останавливает полную запись и спектр.
- Частота кадров по USB 30/50/60/100 кадр/с («Диагностика» → «Связь», команда `A5 'P'`), повторно задаётся после переподключения.
- Измерения: время фронта интерполируется между точками (ошибка частоты на 301 точке была до 0,6 %).
- Спектр: БПФ вместо прямого ДПФ (те же отсчёты, ~1000× быстрее).
- Мощность: Q₁ и cos φ₁ по фазам первых гармоник, отдельно мощность искажений D (раньше Q = √(S²−P²) включала гармоники).
- Лента: в режиме самописца сдвиг кадра выбирается ближе к ожидаемому по времени — периодический сигнал больше не «сжимает» время.
- Связь: при ошибке контрольной суммы пропускается только сигнатура, а не весь кадр (не теряется следующий настоящий кадр).
- Защита локального API (см. выше), экранирование имён файлов/портов/датчиков в HTML.
- Шрифты Inter — WOFF2 с подмножеством символов (2,4 МБ → 0,46 МБ, exe ≈ 7,6 МБ вместо 9,6 МБ); кэш цветов темы; перерисовка «Записей» не чаще кадра анимации.

## Где хранятся данные на ПК

- Настройки: `%APPDATA%\PUFService\settings.json`
- Профиль окна Edge: `%LOCALAPPDATA%\PUFService\window`
- Сохранённые PNG/CSV: `Документы\PUFService`
