# PUFService

Windows-программа для осциллографа FNIRSI 2C53T с доработанной прошивкой RU_USB4 (USB CDC).
Бэкенд на Go (без cgo, без сторонних модулей), интерфейс — встроенная HTML/JS-страница,
которая открывается в окне Edge/Chrome в режиме приложения (`--app`).

## Структура

| Файл / папка | Назначение |
|---|---|
| `main.go` | HTTP-сервер на 127.0.0.1:53153, приём кадров с COM-порта, разбор `FS53`/`MR53`, SSE-поток в интерфейс, API (`/api/*`), записи с диска прибора, настройки, сохранение файлов, запуск окна и автозавершение |
| `sys_windows.go` | Всё, что специфично для Windows: COM-порт через kernel32 (`CreateFile`, `SetCommState`…), поиск порта прибора в реестре (VID 2E3C / PID 5740), список дисков, папки, запуск Edge/Chrome, `MessageBox` |
| `sys_other.go` | Заглушки для Linux/macOS (только для разработки с имитатором) |
| `sim.go` | Имитатор прибора: `--sim` генерирует кадры, отвечает на команды кнопок и чтения памяти |
| `web/` | Интерфейс (встраивается в exe через `go:embed`) |
| `web/app.js` | Вся логика: график, стабилизация, лента, полная запись, спектр, пульт, диагностика, записи, датчики, синхроскоп, мощность, пуск, ШИМ, обороты |
| `web/core.js` | Чтение файлов прибора (.bin + .bmp, распознавание шкал со снимка) и измерения |
| `web/tape.js` | Накопление «ленты» (сшивка кадров в режиме самописца) |
| `res/` | Иконка и ресурс версии для exe (`app.rc`, `app.ico`) |
| `rsrc_windows_amd64.syso` | Скомпилированный ресурс (иконка + версия), Go подхватывает его автоматически |

## Сборка

Нужен Go 1.22+ (проверено на 1.24). Сторонних зависимостей нет.

```bash
# Windows exe (из Linux, macOS или Windows)
GOOS=windows GOARCH=amd64 go build -ldflags "-H windowsgui -s -w" -o PUFService.exe .
```

В Windows (PowerShell):

```powershell
$env:GOOS="windows"; $env:GOARCH="amd64"
go build -ldflags "-H windowsgui -s -w" -o PUFService.exe .
```

`-H windowsgui` убирает консольное окно. Без него удобно отлаживать: в консоль пишутся ошибки.

## Запуск для разработки (без прибора)

```bash
go build -o puf_dev .
./puf_dev --sim --nowindow        # имитатор прибора, сервер без окна
# открыть http://127.0.0.1:53153/ в браузере
```

`STUDIO_ROOTS=/путь/к/папке` (вне Windows) — где искать папки `Screenshot file` / `Screenshot simple file`.

## Иконка и версия exe

При смене версии поправьте `AppVersion` в `main.go`, `v1.x.x` в `web/index.html` и `res/app.rc`, затем пересоберите ресурс:

```bash
cd res
llvm-rc -no-preprocess -fo app.res app.rc
llvm-cvtres /machine:x64 /out:../rsrc_windows_amd64.syso app.res
```

(в Windows можно `windres app.rc -O coff -o ../rsrc_windows_amd64.syso` из MinGW или утилиту `rsrc`/`go-winres`).

## Протокол прибора (прошивка RU_USB4)

USB CDC-ACM, VID `0x2E3C`, PID `0x5740`, скорость порта не важна (виртуальный COM).

**Кадр экрана**, ~30 раз в секунду, всё little-endian:

```
"FS53" | ver(1) | seq(1) | len(u16) | G[0..127] | trace[602] | sys[16] | keyLatch(u16) | keyPhys(u16) | scanCnt(u8) | queue(u8) | injKey(u8) | 0 | sum16(u16)
```

- `G` — первые 128 байт структуры настроек (адрес 0x200000F8): `G[0x2D]` развёртка (индекс 0…28, 10 нс…20 с/дел), В/дел CH1 = `G[6]*3+G[2]`, CH2 = `G[7]*3+G[3]` (индекс 0…12, 10 мВ…100 В), `G[0x14]` маска каналов, `G[4]`/`G[5]` смещение нуля каналов (int8, точки), `G[0x1A..0x1B]` позиция триггера (int16).
- `trace` — 301 точка CH1 + 301 точка CH2 (экранные значения, 128 = центр, 25 точек на деление).
- `sys` — `G[0xF60..0xF6F]` (язык, страница, курсор меню).
- `sum16` — сумма всех предыдущих байтов кадра.

**Ответ на чтение памяти:**

```
"MR53" | 1 | seq | len(u16) | addr(u32) | data[n] | sum16
```

**Команды в прибор** (байты в COM-порт):

| Команда | Байты | Действие |
|---|---|---|
| Нажать кнопку | `A5 'K' idx hold` | кнопка 0…14 удерживается `hold` опросов (короткое ≈6, длинное ≈90) |
| Отмена | `A5 'X' 0 0` | очистить очередь нажатий |
| Период кадров | `A5 'P' ms 0` | период отправки кадров, мс (≥10) |
| Чтение памяти | `A5 'M' addr(u32) len(u16)` | ОЗУ 0x20000000…0x20038000 или флеш 0x08000000…0x08100000, до 2048 байт |

Полная запись захвата: буфер А (CH1) `0x200006A8`, буфер Б (CH2) `0x20000AA8`, по 1024 байта.
Шаг точек относительно экрана программа определяет сама, сопоставляя кадр экрана с буфером (`deepMatch` в `app.js`).
